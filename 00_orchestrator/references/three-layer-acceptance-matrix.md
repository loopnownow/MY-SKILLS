## 0 验收要回答的问题

三层拆分是文件重组还是真的改变了产出质量？具体回答四问：

1. **Base-only 是否够用**：不加载任何 advanced 个人修订时，科学质量是否已经达标？
2. **Advanced 是否只加人味、不加错误**：加上 S3 个人修订后，科学错误 / 无证据主张 / 数值一致性是否不变差，个人偏好执行是否变好？
3. **Style QC 是否只在该跑时跑**：QCV 是否没有混进科学总分、没有造成误报与不必要改写？
4. **瘦身是否降低了上下文负担**：同样的任务，加载的 base 字节数 / 文件数是否显著下降，而漏检没有上升？

## 1 实验臂（arms）

| 臂 | 组成 | 说明 |
|---|---|---|
| A：Base-only | 00 识别 → base 首跑 → 00 科学 QC（QCS）→ 停 | 不加载 advanced 任何文件，不跑 QCV；代表"新架构的最小能力" |
| B：Base+Advanced | A + S3 advanced 个人修订 + S4 增量 QC + 可选 Style QC（QCV） | 代表"城城实际工作流"；QCV 只在改动段落跑 |
| C：重构前基线（对照） | 旧 tip `04a4c35` 的技能树，同任务同模型 | 只用一次，估计拆分本身带来的净变化；不是回归门槛 |

臂 A 与臂 B 必须同模型、同 prompt、同输入、同 seed（若模型支持）；对照臂 C 仅作参考，不参与 PASS/FAIL 判定。

## 2 任务与固定输入（fixtures）

四个任务各准备一份冻结输入（去标识；不含 PHI/PII；放在一次性 fixture 目录，验收后删除）：

| 任务 | 入口 fine id | 输入（冻结） | 关注点 |
|---|---|---|---|
| T1 统计 | `stats-analysis` | 一份含设计、样本量、主要/次要结局、假设检验结果表、校准与 DCA 结果的分析方案 + 结果摘要（Markdown） | 检验选择是否按设计、HL/DCA 表述是否不过宽、数值是否忠实 |
| T2 设计 | `design-study` | 一段真实形态的课题草稿（病种/模态/n/中心数/标签来源/随访）+ 3 条相互冲突的可行性约束 | 是否先问缺失输入、是否给出可行性裁决、是否守住 valid≠external |
| T3 写作 | `write-paper` | 一份 Results + Discussion 草稿（含 2 处无引用强主张、1 处数值与表不一致） | 无证据主张是否被标、数值是否对齐、是否不必要改写 |
| T4 审稿 | `peer-review` | 一份匿名稿件片段 + 审稿要求（英文审稿意见 3-5 条） | 是否区分"科学问题"与"表达偏好"、是否越权改写、是否给可执行 locator |

fixture 要求：每份输入只描述事实，不暗示期望答案；同一份输入四个任务各跑一次 A、B（C 可选），共 8–12 次运行。

## 3 评分（由独立 QC 盲评）

评分人不知道产物来自 A 还是 B（产物去臂标签、随机排序）。评分只用 QCS/QCV 的既有字段，不另造口径：

| 指标 | 来源 | 计分 |
|---|---|---|
| 科学错误数 | QCS blocker + major | 计数，越低越好 |
| 无证据主张数 | QCS（claim / citation / AL-5 类） | 计数 |
| 数值一致性错误 | QCS（claim-number-align / stat_vs_threshold 类） | 计数 |
| 改写（二分） | 人工 diff 按句计数，再分两类：**必要重构**（house 结构、规则要求的改写）与**无谓改写**（同义替换、无依据润色） | 两列计数；门槛只对无谓改写 |
| 个人偏好执行 | QCV 检查表命中数（Aitor 结构、vocab、句长、paragraph lock） | 计数；A 臂预期低、B 臂预期高 |
| 误报 | QCV/QCS 报了但实际不成立 | 计数 |
| 上下文负担 | 运行时加载的文件数，以及**主 base pack 字节**（任务入口所在 `NN_slug/base/<pack>/` 的 .md 合计，不含 00 共用开销） | 两列数值 |

补充要求：每个产物同时记录"加载了哪些文件"（路径清单），用于第 7 项与复现。

## 4 判定规则（预注册，验收前不得改）

1. **科学不回退**：B 的科学错误数 ≤ A（允许 +0；若 B 比 A 多 1 个 blocker 即 FAIL）。
2. **个人偏好确实执行**：B 的 QCV 命中数 ≥ A + 2（结构/vocab 层面），否则 advanced 层等于没用。
3. **Style QC 不越界**：B 臂中 QCV 的 FAIL-SOFT 不得导致任何科学 gate 阻断；抽查 3 条 QCV 命中，误报 ≤ 1。
4. **无谓改写不上升**：B 的**无谓改写**句数 ≤ A + 1；必要重构不计入门槛，但须在 verdict 逐条列出触发它的规则或 house 结构。
5. **上下文负担下降**：同任务**主 base pack 字节**比旧 tip `04a4c35` 下降 ≥ 20%（不含 00 共用文件；对照用 `git ls-tree` 统计同一目录，不要求复跑 C 臂）。若 base 主动承接了原 advanced 的通用内容（如 06 的 review envelope），该任务记为 EXEMPT 并在 verdict 说明，不计 FAIL。
6. 任一条 FAIL：回到对应 PR 修规则或指针，修完重跑受影响任务（只重跑该项，不整批）。

## 5 执行顺序（建议两轮）

1. 先跑 T1（统计）：最容易客观判分，先校准评分人之间的口径。
2. 再跑 T2（设计）与 T4（审稿）：检查 handoff 与"什么时候该问"。
3. 最后跑 T3（写作）：改写率与 QCV 误报在这里最敏感。
4. 每轮结束写一页：arm × metric 矩阵 + 3 条结论 + 1 条下一步动作。

## 6 交付物（验收包）

- `score-matrix`：8–12 行 × 7 列的评分矩阵（行=运行，列=指标）。
- `loads/`：每次运行的加载文件清单（路径 + 字节）。
- `diffs/`：两臂相对输入的产物 diff。
- `verdict`：逐条对照 §4 的 PASS/FAIL + 证据行号，最后一句给"接受 / 接受但列后续修 / 不接受"。

## 7 已知限制

- 独立 QC 仍是同一个 agent 体系，存在自证偏置；至少让评分人拿到"去臂标签"的产物，且评分时不得读两臂的运行记录。
- 单次运行方差大：若时间允许，T1 与 T3 各跑 2 次取均值；否则在 verdict 里注明单次。
- 本矩阵不覆盖 journal-format-compliance 与 track-changes 的版式验收；那两项走各自的格式检查。
- advanced 的"个人偏好执行"依赖城城真实语料；fixture 里的期望结构以 `05_manuscript/advanced/Aitor-format.md` 与 `advanced/vocab/` 为准，不另建标准。

- B 臂 = S0→S4（… → advanced 修订 → 增量 QC + 可选 QCV）；S5 复检只对 B 的 FAIL 项执行。
